## IMPLEMENTED

- Extended the timeline domain types with the WS10 canonical intermediate representation:
  - `TimelinePlan` — deterministic `id`, derived `durationMs`, ordered `segments`
  - `TimelineSegment` — `startMs`, `endMs`, referenced `AssetId[]`, optional `audioAssetId`, optional `captionTrack` (CaptionTrack imported from `src/domain/captions`, not copied)
  - Draft variants `TimelinePlanDraft` / `TimelineSegmentDraft`
- Added deterministic builder `src/domain/timeline/timeline-builder.ts`:
  - `buildTimeline()` / `buildTimelineSegment()` use `deterministicId()` + `stableJson()`; no randomness, no current time
  - segments canonicalized (sorted `assetIds`, optional fields only when present) and ordered by `startMs` with stable JSON tie-break, so identical input orderings produce identical output
  - `durationMs` derived from the max segment `endMs`
- Added boolean validation (no throw on normal failure) in `src/domain/timeline/validation.ts`:
  - `isTimelineSegment` / `isTimelinePlan` reject negative timestamps, `endMs <= startMs`, overlapping segments, caption timings outside the owning segment, invalid/duplicate asset references, non-canonical ids/order
  - `validateTimelinePlan` returns `{valid, issues}` mirroring the WS4 `validateTimeline` convention
  - Deterministic-id integrity enforced by re-deriving the expected plan via `buildTimeline()` and comparing ids (WS4 `isTimeline` convention)
- Caption integration: `isTimelineSegment` reuses `isValidCaptionTrack` from WS9; no caption logic duplicated. No circular imports (`captions` never imports `timeline`).
- Exports: `timeline/index.ts` now also re-exports `./timeline-builder`.

Naming note: WS4 already owns the frame-based runtime `Timeline` type. To avoid a barrel `export *` name collision, the WS10 ms-based canonical model is named `TimelinePlan` + `TimelineSegment` (same domain, distinct concept).
